サイズ、分布、統計

pbtでは、データがどんな姿になるかを利用者が決め、意図したとおりになっているかを確かめる手段も利用者が持ちます。この2つは対になっています。システムの興味深い状態に到達しないプロパティは、その状態について何も証明しません。

サイズパラメーター

すべてのテストケースはサイズを持って実行されます。Check はサイズ1から始め、ケースが通過するごとに1ずつ、42まで増やします。実行は小さな入力で始まり、大きな入力で終わります。文字列、スライス、マップの長さはサイズを平均とし、整数の大きさもサイズとともに増えます。t.Size() は現在のケースのサイズを返します。Sizes(start, max) オプション、またはフラグ -pbt.startsize と -pbt.maxsize で範囲を変えられます。

Sized はサイズから生成器を組みます。PropErの ?SIZED と同じ働きです。Resize は生成器を固定したサイズで動かします。2つを組み合わせると、再帰的な構造に上限を付けられます。

// A tree whose depth follows the size parameter: small early cases, larger
// later ones. Resize fixes the size of a part of a value.
type Tree struct {
	Value    int
	Children []Tree
}

func tree() pbt.Gen[Tree] {
	return pbt.Sized(func(size int) pbt.Gen[Tree] {
		if size <= 1 {
			return pbt.Map(pbt.Int(), func(v int) Tree { return Tree{Value: v} })
		}
		return pbt.Custom("tree", func(t *pbt.T) Tree {
			child := pbt.Resize(size/2, tree())
			return Tree{Value: pbt.Int().Draw(t, ""), Children: pbt.SliceOfN(child, 0, 3).Draw(t, "")}
		})
	})
}

段ごとにサイズを半分にすると、分岐の数がいくつでも、木の深さはサイズの対数以下に収まります。Resize(0, g) はコレクションを空にします。コレクションから組み上げる値の、最小のケースです。

重み

Frequency は、重みに比例した確率で選択肢の1つから値を取り出します。

type Op struct {
	Kind string
	Key  string
}

// ops reads four times as often as it writes; shrinking moves toward the
// first alternative, the read.
var ops = pbt.Frequency(
	pbt.Weighted[Op]{Weight: 4, Gen: pbt.Map(pbt.StringN(1, 3), func(k string) Op { return Op{"get", k} })},
	pbt.Weighted[Op]{Weight: 1, Gen: pbt.Map(pbt.StringN(1, 3), func(k string) Op { return Op{"put", k} })},
)

重みが影響するのは生成だけです。縮小は重みに関係なく常に先頭の選択肢へ向かうので、選択肢の並び順が縮小の優先順位になります。重み0の選択肢は生成されず、縮小によってだけ到達できます。3章の ShrinkTo はこの性質の上に組んであります。OneOf は重みが等しい Frequency です。

統計

*pbt.T の4つのメソッドが、実行したケースの様子を記述します。プロパティが通過すると Check が結果を表示します。

func TestOperationMix(t *testing.T) {
	pbt.Check(t, func(t *pbt.T) {
		batch := pbt.SliceOfN(ops, 1, 20).Draw(t, "batch")
		writes := 0
		for _, op := range batch {
			t.Aggregate(op.Kind) // share of each kind among all operations
			if op.Kind == "put" {
				writes++
			}
		}
		t.Classify(writes == 0, "read-only batch") // share of cases
		t.Measure("batch length", float64(len(batch)))
		t.Cover(writes > 0, 60, "has a write")
	}, pbt.CheckCoverage())
}
  • Classify(cond, label) は条件が成り立ったケースを数え、Collect(v) は値の文字列表現ごとにケースを数えます。どちらもケース全体に対する割合として報告されます。
  • Aggregate(values...) は1ケースに複数あるサンプルを数え、サンプル全体に対する割合として報告します。ステートフルテストが実行したコマンドの名前に向いています。
  • Measure(name, value) は数値を記録し、最小、平均、最大を報告します。
[pbt] OK, passed 100 checks (seed 0x1)
[pbt]  22.0% read-only batch
[pbt]  81.1% get
[pbt]  18.9% put
[pbt] batch length: min 1, avg 12.43, max 20 (100 samples)

割合は4対1の重みどおりで、長さの行は上限いっぱいのバッチも出ていることを示しています。Verbose() か -pbt.v を付けると、プロパティが何も記録していなくても要約が出ます。

カバレッジを検査する

Cover(cond, pct, label) は観察を要求に変えます。cond が成り立つケースが、全ケースの pct パーセント以上を占めなければならない、という要求です。上の例では、バッチの60%に書き込みが含まれることを要求しています。

100ケースの実行が偶然60%を下回ることはあるので、判定は統計的に行います。pbtは観測した割合の99.7%信頼区間であるWilsonスコア区間を計算します。区間全体が pct を上回れば充足、下回れば不足、pct をまたいでいる間は未決です。CheckCoverage オプションがなければ、Check は不足をログに出して通過します。オプションがあると、Check はすべての要求が決まるまで、設定した回数の20倍を上限にケースを走らせ続けます。不足なら失敗し、要求が未決のまま終わったときも失敗します。通過したなら、データがその割合を裏付けています。

var rareCoverProperty = func(t *pbt.T) {
	n := pbt.IntRange(0, 999).Draw(t, "n")
	t.Cover(n%100 == 0, 30, "round hundred") // too rare for a 30% share
}

[pbt] insufficient coverage:
[pbt]   round hundred: 17.6% of 125 cases, required 30.0%

区間が30%を除外した時点、つまり125ケースで実行は止まりました。観測された割合は IntRange についても教えてくれます。0は境界値なので、1000分の1よりずっと頻繫に出ているのです。統計はそれを知る手段で、一様な分布がプロパティに必要なときに分布を変える手段が Frequency や SampledFrom です。
