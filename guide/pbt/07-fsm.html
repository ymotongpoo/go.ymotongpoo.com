State machines

When a system moves between named states and allows different operations in each, a finite state machine is the natural model. The fsm package builds on the command machinery of chapter 5: you name the states and list the transitions out of each one, with weights, and the package generates command sequences that follow the machine. It is the counterpart of PropEr's proper_fsm.

The system

// Account moves between the states new, verified and locked.
type Account struct{ state string }

var errState = errors.New("not allowed in this state")

func (a *Account) Verify() error { return a.move("new", "verified") }
func (a *Account) Lock() error   { return a.move("verified", "locked") }
func (a *Account) Unlock() error { return a.move("locked", "verified") }

func (a *Account) move(from, to string) error {
	if a.state != from {
		return errState
	}
	a.state = to
	return nil
}

The machine

A machine implements fsm.Machine[N, D, Sys]: N is the type of the state names, D the state data carried alongside the name, and Sys the system under test. Initial returns the first state, and Transitions returns the transitions available in a state.

// accountMachine names the states and lists the transitions out of each
// one. The state data is empty here; a machine can carry a model value too.
type accountMachine struct{}

func (accountMachine) Initial() (string, struct{}) { return "new", struct{}{} }

func (accountMachine) Transitions(state string, _ struct{}) []fsm.Transition[string, struct{}, *Account] {
	type cmd = pbt.Cmd[struct{}, *Account]
	expect := func(want error) func(struct{}, pbt.Env, any) error {
		return func(_ struct{}, _ pbt.Env, got any) error {
			err, _ := got.(error)
			if !errors.Is(err, want) {
				return errors.New("unexpected result")
			}
			return nil
		}
	}
	command := func(name string, call func(*Account) error, want error) pbt.Gen[pbt.Command[struct{}, *Account]] {
		return pbt.Just[pbt.Command[struct{}, *Account]](cmd{Name: name, Run: func(a *Account, _ pbt.Env) any { return call(a) }, Post: expect(want)})
	}
	type transition = fsm.Transition[string, struct{}, *Account]
	switch state {
	case "new":
		return []transition{
			{Weight: 3, To: "verified", Cmd: command("verify", (*Account).Verify, nil)},
			{Weight: 1, To: "new", Cmd: command("lock", (*Account).Lock, errState)},
		}
	case "verified":
		return []transition{
			{Weight: 2, To: "locked", Cmd: command("lock", (*Account).Lock, nil)},
			{Weight: 1, To: "verified", Cmd: command("verify", (*Account).Verify, errState)},
		}
	default: // locked
		return []transition{
			{Weight: 2, To: "verified", Cmd: command("unlock", (*Account).Unlock, nil)},
			{Weight: 1, To: "locked", Cmd: command("lock", (*Account).Lock, errState)},
		}
	}
}

func TestAccountMachine(t *testing.T) {
	pbt.Check(t, func(t *pbt.T) {
		prog := fsm.Commands[string, struct{}, *Account](accountMachine{}).Draw(t, "cmds")
		prog.RunSequential(t, &Account{state: "new"})
	})
}

Each Transition has a Weight, a target state To, and a Cmd, a generator of commands over the state data. The command's Pre, Next and Post see the data, not the name; the machine moves the name. A transition that stays in the same state, like a second verify in verified, is how a machine tests the operations that must be rejected.

fsm.Commands(m) returns a generator of programs whose model state is fsm.State[N, D], the pair of name and data. The program runs with RunSequential as in chapter 5, and fsm.ParallelCommands gives the parallel form of chapter 6.

Statistics by state

The commands are labeled with their source state, so the summary of a passing run shows which transitions the machine took:

[pbt] OK, passed 100 checks (seed 0x1)
[pbt]  32.7% verified: lock
[pbt]  31.5% locked: unlock
[pbt]  17.2% verified: verify
[pbt]  15.1% locked: lock
[pbt]   2.8% new: verify
[pbt]   0.7% new: lock

The low share of new is expected: every sequence leaves that state after one or two commands and never returns. If a state matters and the statistics show that sequences rarely reach it, raise the weights of the transitions that lead there.
