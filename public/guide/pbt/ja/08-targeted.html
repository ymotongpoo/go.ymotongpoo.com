標的型探索と存在性

ランダムな入力は、システムのよくある状態にはすぐ到達しますが、まれな状態には遅いか、到達しません。標的型プロパティベーステストは効用関数を加えます。プロパティが、ケースが興味深い何かにどれだけ近づいたかを報告し、pbtは新しいケースを引く代わりに効用の高いケースを探します。PropErでは ?MAXIMIZE です。

Maximize

// A random walk rarely ends far to the right of the origin. Maximize turns
// the run into a search for walks that do, and the property fails once one
// gets past 50; without the search, 100 random cases would almost never
// fail.
var walkProperty = func(t *pbt.T) {
	steps := pbt.SliceOf(pbt.SampledFrom([]int{-1, 1})).Draw(t, "steps")
	pos := 0
	for _, s := range steps {
		pos += s
	}
	t.Maximize("position", float64(pos))
	if pos > 50 {
		t.Fatalf("the walk reached %d", pos)
	}
}

n 歩のランダムウォークは原点から sqrt(n) ほどの距離で終わるので、100回のランダムな歩みが50に届くことはまずありません。t.Maximize("position", pos) があると、最初のケースが効用を報告した時点で実行は探索に変わります。pbtはそれまでで最良のケースの選択を変異させ、効用が高ければその変異を残し、局所的な最大から抜けるために探索の早い段階では悪い変異も時々残し、ときどき新しいケースからやり直します。探索は、チェック数ではなく SearchSteps か -pbt.searchsteps で決めたステップ数（デフォルトは1000）だけ続きます。

[pbt] property failed after 246 passed checks and 1835 shrink steps (size 33)
[pbt] utility position = 51
[pbt] steps (SliceOf(SampledFrom(2 values))) = []int{1, 1, 1, 1, …}
[pbt] error: the walk reached 51

探索は246ケースで50を超える歩みを見つけ、縮小器がそれを右への51歩、つまり失敗する最小の入力まで減らしました。プロパティが通過したときは、要約に観測した最良の効用が載ります。t.Minimize は逆向きに探索します。1つのケースの効用は1つです。同じ名前で Maximize を再び呼ぶと値が置き換わり、別の名前で呼ぶとエラーになります。

「近さ」の概念があるプロパティで探索を使ってください。木の深さ、キューの長さ、再試行の回数、境界までの距離などです。大半の入力で平らな効用は、探索に登る手がかりを与えません。

存在性

CheckExists は問いを逆にします。すべてのケースで成り立つべきプロパティではなく、プロパティが成り立つケースを1つ探します。失敗したケースは却下された候補で、最初に通過したケースが証拠になります。pbtはその証拠を縮小してログに出します。

// CheckExists succeeds once a case passes: here, a Pythagorean triple. The
// witness is shrunk and logged.
func TestATripleExists(t *testing.T) {
	pbt.CheckExists(t, func(t *pbt.T) {
		a := pbt.IntRange(1, 50).Draw(t, "a")
		b := pbt.IntRange(1, 50).Draw(t, "b")
		c := pbt.IntRange(1, 70).Draw(t, "c")
		if a*a+b*b != c*c {
			t.Fail()
		}
	}, pbt.Checks(5000))
}

[pbt] witness found after 2748 rejected cases and 14 shrink steps (seed 0x83d3334683123f8d) (size 42)
[pbt] a (IntRange(1, 50)) = 3
[pbt] b (IntRange(1, 50)) = 4
[pbt] c (IntRange(1, 70)) = 5

チェック数の範囲で証拠が見つからないとテストは失敗します。CheckExists の中でも Maximize は働きます。通過するケースまでの距離を測る効用が、探索をそこへ導きます。存在性のプロパティでは testdata/pbt に何も保存されません。証拠は回帰ケースではないからです。
